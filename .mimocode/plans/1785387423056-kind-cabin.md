# Milestone Assignment System — Implementation Plan

## Overview
Allow companies to create milestones and assign them to specific hired freelancers. Each freelancer only sees and completes their own milestones. No database schema changes needed — `milestones.freelancer_id` column already exists but is never populated.

## Key Finding
The `milestones` table already has `freelancer_id INT DEFAULT NULL` with an index (`idx_milestones_freelancer`). The column was added by migration but **no code ever writes to it**. This is a wiring fix, not a schema change.

### 2. `company/view_applications.php` — Add milestone creation + fix queries

#### 2a. Add "create_milestone" POST handler (after line ~315, inside the `ms_action` block)

New handler for `ms_action === 'create_milestone'`:
- Validate: title required, amount > 0, freelancer_id must be valid assignment for this job
- INSERT into milestones with `freelancer_id`, `job_id`, title, description, amount, deadline, status='draft', sort_order=MAX+1
- PRG with flash message

#### 2b. Add freelancer dropdown in milestone creation form (after line ~497, before milestone display)

Fetch accepted freelancers:
```sql
SELECT a.freelancer_id, f.full_name, u.profile_image
FROM assignments a
JOIN freelancers f ON f.id = a.freelancer_id
JOIN users u ON f.user_id = u.id
WHERE a.job_id = ? AND a.status != 'completed'
ORDER BY f.full_name
```

Display a card with form: title, description, amount, deadline, freelancer dropdown.

#### 2c. Add "Assigned To" column in milestones display (~line 628)

Change milestone fetch query (line ~557) to JOIN freelancers:
```sql
SELECT m.*, e.status AS escrow_status, e.funded_at, e.released_at,
       f.full_name AS assigned_freelancer_name
FROM milestones m
LEFT JOIN escrow e ON e.milestone_id = m.id
LEFT JOIN freelancers f ON f.id = m.freelancer_id
WHERE m.job_id = ?
ORDER BY m.sort_order ASC
```

Show `assigned_freelancer_name` (or "Unassigned") in each milestone row.

#### 2d. Fix approve notification to use milestone's freelancer_id (~line 418)

**Current:** Resolves freelancer from ANY assignment on the job:
```sql
SELECT u.id FROM assignments a JOIN freelancers f ON a.freelancer_id = f.id JOIN users u ON f.user_id = u.id WHERE a.job_id = ?
```

**Fix:** Resolve from milestone's freelancer_id:
```sql
SELECT u.id FROM freelancers f JOIN users u ON f.user_id = u.id WHERE f.id = ?
```
Bind `$ms['freelancer_id']` (fetch milestone with freelancer_id before approve action).

#### 2e. Fix revision notification (~line 473)

Same fix as 2d — use milestone's freelancer_id instead of job's assignment.

#### 2f. Fix payment assignment_id resolution (~line 372)

**Current:** Gets ANY assignment for the job:
```sql

```

**Fix:** Get the specific freelancer's assignment:
```sql
SELECT a.id FROM assignments a WHERE a.job_id = ? AND a.freelancer_id = ?
```
Bind `$job_id` and `$ms['freelancer_id']`.

#### 2g. Fix assignment status updates on approve (~line 402, 408)

**Current:** Updates ALL assignments for the job:
```sql
UPDATE assignments SET status = 'completed' WHERE job_id = ?
UPDATE assignments SET status = 'working' WHERE job_id = ? AND status = 'submitted'
```

**Fix:** Update only the specific freelancer's assignment:
```sql
UPDATE assignments SET status = 'completed' WHERE job_id = ? AND freelancer_id = ?
UPDATE assignments SET status = 'working' WHERE job_id = ? AND freelancer_id = ? AND status = 'submitted'
```

Also fix the "all milestones approved" check to only check milestones for the current freelancer, not all milestones for the job.

### 4. `freelancer/milestone.php` — Add freelancer_id authorization

#### 4a. Start action (~line 15-24)

**Current:**
```sql
SELECT m.id, m.job_id, m.status
FROM milestones m
JOIN assignments a ON a.job_id = m.job_id AND a.freelancer_id = ?
WHERE m.id = ? AND m.status = 'funded'
```

**Fix:** Add milestone.freelancer_id check:
```sql
SELECT m.id, m.job_id, m.status
FROM milestones m
JOIN assignments a ON a.job_id = m.job_id AND a.freelancer_id = ?
WHERE m.id = ? AND m.status = 'funded'
  AND (m.freelancer_id = ? OR m.freelancer_id IS NULL)
```
Bind `$fl_freelancer_id` twice (once for assignments, once for milestones).

#### 4b. Submit action (~line 51-56)

Same pattern — add `AND (m.freelancer_id = ? OR m.freelancer_id IS NULL)`.

#### 4c. View authorization (~line 135-147)

Same pattern — add `AND (m.freelancer_id = ? OR m.freelancer_id IS NULL)` to the WHERE clause.

#### 4d. Sidebar milestones list (~line 157)

Filter by freelancer_id:
```sql
SELECT id, title, amount, status, sort_order FROM milestones WHERE job_id = ? AND (freelancer_id = ? OR freelancer_id IS NULL) ORDER BY sort_order ASC
```

#### 4f. Assignment status update on submit (~line 85-90 area)

Same fix — target specific freelancer's assignment.

### 5. `migrations/backfill_milestone_freelancer.php` — New file

Backfill existing direct-hire milestones:
```sql
UPDATE milestones m
JOIN assignments a ON a.job_id = m.job_id AND a.assignment_type = 'direct_hire'
SET m.freelancer_id = a.freelancer_id
WHERE m.freelancer_id IS NULL
```
